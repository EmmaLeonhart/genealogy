A supervisor for the download, because the machine interrupts it constantly

Emma: "it will be constantly interrupted, this is why I asked for it to be
easily resumable". Resumability alone is not enough if a human has to notice
and restart it, so scripts/wikidata-tick.ps1 does one bounded chunk (~20,000
items, about eleven minutes) and then commits and pushes whatever landed. Fire
it on a schedule and the download makes progress across interruptions without
anyone watching.

The moment restarting is automatic, the failure mode becomes two copies running
at once, both appending to the same shard -- which corrupts the store rather
than merely wasting requests. So StateIndex now holds a single-run lock. It is
a heartbeat refreshed every round, not a PID file: a killed run stops beating
and its lock ages out on its own, so there is no cleanup step to forget and
nothing to check against a process table. A clean exit releases it immediately.
A garbled heartbeat value does not wedge the lock forever.

The tick script writes its commit message to a file rather than using -m or a
here-string: PowerShell 5.1 has no heredoc and mangles < and > in
native-command arguments, both already recorded in CLAUDE.md.
