# Audit — "En dödfödd son Bielke", and the edit war it caused

**Emma, 2026-08-30:** *"an item was created as 'En dödfödd son Bielke' which is just wrong."*
And, on the same item: *"please stop trying to assign names to this person who does not in fact
have any names at all."*

The item is `Q141224141`. Geni records the child as `En dödfödd son` `/Bielke/` — Swedish for
*a stillborn son*. That is a description standing in for an absent name.

`Q69523615` is the given name **`En`** — the Swedish indefinite article, *a*. `Q20111831` is a
male given name item with no label at all. `Q37547315` *Bielke* is the one legitimate statement.

**The label half was already right.** `mul` reads `NN Bielke`, which is exactly `CLAUDE.md`
§ *The NN/Private label algorithm* — marker plus the surname that survives redaction. So the
label path recognised this person as unnamed while the name-item path did not.

## Two defects, and one of them was documented but never implemented

**1. The stillborn vocabulary was never added to anything.** `scripts/labels.py` carries a
detailed comment block about this exact item — quoting her, naming the counts, citing her
standing rule that *an obvious unknown-word marker goes straight in*. The words
`dödfödd`, `dødfødt`, `stillborn` are **in neither `labels.WORDS_MEANING_UNKNOWN` nor
`namemodel.UNKNOWN_MARKERS`**. The comment describes a fix that was never made. A note claiming
a fix is worse than no note, because it reads as done.

**2. `name_shape` never ran on the given-name field.** `classify_fields` applied it to `SURN` and
`_MARNM` only, so every marker already in `UNKNOWN_MARKERS` became a `given` name when it sat in
`GIVN`:

    classify_fields(givn="NN",      surn="Garborg") -> [('NN', 'given', 1), ('Garborg', 'family', 0)]
    classify_fields(givn="Unknown", surn="Smith")   -> [('Unknown', 'given', 1), ('Smith', 'family', 0)]

The set existed; the field simply never consulted it.

## Measured over `reports/display-names.csv`, 2026-08-31

- **15,101 people** carry a token in `GIVN` that `name_shape` now calls `unknown` and previously
  returned as a given name — `nn` 7,527, `n.n.` 3,871, `unknown` 1,608, `?` 1,405, `ukjent` 222,
  `okänd` 89.
- **470 people** have a `GIVN` that is a stillbirth description — `dødfød` 212, `dødfødt` 208,
  `stillborn` 135, `dödfödd` 112, `dödfött` 19.

## The fix

`namemodel.DESCRIPTION_MARKERS` holds the stillbirth words, and it is deliberately **stronger**
than `UNKNOWN_MARKERS`: a marker suppresses its own token, a description marker suppresses the
**whole given-name field**. The words around it — `En`, `son` (43), `barn` (17), `gossebarn` (15),
`daughter` (14) — are the rest of one phrase, not names standing next to it. Her sentence is the
authority for going that far: *does not in fact have any names at all*.

`name_shape` now runs on `GIVN`, and a description also suppresses the nickname the bracketed
form would otherwise produce — `(--stillborn--)` occurs 11 times and `QUOTED` reads it as a
byname, so without that it reaches Wikidata as an `Amul` alias instead of a `P735`.

The surname is untouched throughout. `Bielke` still becomes `P734`, so the person keeps a family
name and the `NN Bielke` label and loses only what was never a name.

**The reading taken rather than asked** (`CLAUDE.md` § *Working the queue: GUESS*): a real given
name recorded beside a stillborn word would be dropped with it. It would be falsified by a `GIVN`
like `Anna dödfödd`, and there is none — every co-occurring token measured is structural.

`tests/test_namemodel.py` pins all of it, including that an ordinary name and a genuine quoted
nickname are untouched.

## Not fixed

`Q141224141` still holds nothing wrong — she cleared it twice and the generator will no longer
re-add anything. The other items already created from a stillbirth description are not audited
here.
